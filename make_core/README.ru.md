# make_core: файлы ядер Karabas (.kg1 / .kg2 / .kg3)

[English version](README.md) · Протокол MCU ↔ FPGA: [karabas-go-firmware/docs/protocol.ru.md](https://github.com/andykarpov/karabas-go-firmware/blob/master/docs/protocol.ru.md)

В файле ядра собрано всё, что нужно прошивке RP2040 для запуска ядра:

- битстрим FPGA;
- ROM, которые загружаются в ядро;
- меню OSD;
- настройки ядра: имя, тип, банк EEPROM, режим RTC, частота SPI, параметры file loader.

`make_core.py` собирает такой файл из описания в JSON (`core.json`).

| Плата | Расширение | Обычное имя JSON |
|---|---|---|
| Karabas Go | `.kg1` | `core.json` |
| Karabas Mini | `.kg2` | `core_mini.json` |
| Karabas Mini G | `.kg3` | `core_minig.json` |

Формат у всех трёх одинаковый. Расширение лишь говорит прошивке, для какой платы битстрим, поэтому для каждой платы нужен свой битстрим и свой файл.

## Сборка файла ядра

```
python3 make_core.py <core.json> <выходной файл>
```

Пути внутри JSON (`bitstream`, `filename` у ROM) считаются от **текущего каталога**, поэтому запускайте скрипт из того каталога, на который ссылается JSON. Типичный скрипт в репозитории ядра (`src/`):

```sh
python3 make_core.py core.json       tsconf.kg1
python3 make_core.py core_mini.json  tsconf.kg2
python3 make_core.py core_minig.json tsconf.kg3
```

Битстрим — это `.bin` из ISE (`bitgen -g Binary:yes`). Готовые файлы кладутся в корень SD-карты, там же должно лежать boot-ядро (`boot.kg1/2/3`).

## Справочник по core.json

Файл должен быть строгим JSON: без комментариев и без висячих запятых (`{...},` перед `]`).

### Верхний уровень

| Ключ | Тип | Обязателен | Смысл |
|---|---|---|---|
| `id` | строка, ≤ 32 | да | Идентификатор ядра. |
| `name` | строка, ≤ 32 | да | Имя в списке ядер. |
| `build` | строка, ≤ 8 | да | Номер сборки / версии, обычно `ГГММДДЧЧ`. |
| `bitstream` | путь | да | Битстрим FPGA (`.bin`). |
| `visible` | bool | да | Показывать ли ядро в списке ядер boot-меню. |
| `order` | 0–255 | да | Порядок в списке ядер. |
| `type` | строка | да | `boot`, `osd`, `fileloader`; любое другое значение (например, `hidden`, `none`) — без OSD. См. ниже. |
| `eeprom_bank` | 0–255 | да | `0`–`3`: банк встроенной EEPROM 24C08; `4`–`254`: 256 байт внутри файла ядра; `255`: без EEPROM. |
| `rtc_mode` | 0–3 | нет (0) | Модель регистров RTC: `0` MC146818A, `1` DS1307, `2` ZX Evolution (MC146818A, всегда BCD), `3` MSM6242B (Amiga, 13 BCD-цифр; прошивка с поддержкой MSM6242B). |
| `spi_freq` | МГц | нет (0) | Частота SPI-линка MCU ↔ FPGA для этого ядра. `0` — по умолчанию, 16 МГц. |
| `save_dir` | строка | нет | Каталог файлов backup RAM (`.sav`) ядра с backup RAM (бит 3 в caps, `docs/protocol.md` прошивки, «Backup RAM»), до 32 символов. Не задан — `<dir>/saves`. |
| `buttons` | объект | нет | Действия кнопок на плате, см. ниже. Не задано — кнопка уходит в ядро. |
| `matrix` | строка / объект | нет | Что показывает LED-матрица, см. ниже. Не задано — ею управляет ядро. |
| `dir` | строка, ≤ 32 | нет | Для ядер `fileloader`: начальный каталог на SD-карте. |
| `extensions` | строка, ≤ 32 | нет | Для ядер `fileloader`: допустимые расширения через запятую (`.rom,.bin`). |
| `filename` | строка | нет | Оставляйте пустой (`""`) или не указывайте: в этом поле прошивка хранит последний выбранный файл. |
| `roms` | массив | да (можно `[]`) | ROM, см. ниже. |
| `osd` | массив | да (можно `[]`) | Пункты меню OSD, см. ниже. |

Типы ядер:

- **`boot`** — boot-меню. Его OSD — браузер ядер на SD-карте. Если видеочип FT812 установлен и включён, браузер рисует FT812.
- **`osd`** — обычное ядро. Меню OSD открывается по `Menu+Esc`.
- **`fileloader`** — при старте сразу открывается выбор файла из `dir` / `extensions`. Выбранный файл отправляется ядру командами file loader. `Menu+Esc` снова открывает выбор файла.
- **любое другое значение** — OSD нет вовсе.

### Кнопки

`buttons` задаёт, что делают кнопки на плате в этом ядре. Ключи `btn1`, `btn2` (`btn3`..`btn6` зарезервированы под доп. кнопки Karabas Mini G). Значение — имя действия или объект:

| Ключ | Значение |
|---|---|
| `press` | Действие по нажатию. По умолчанию `core`. |
| `hold` | Действие по удержанию `hold_ms`. По умолчанию нет. |
| `hold_ms` | 100–25400 мс, по умолчанию 2000. |

Действия:

| Действие | Значение |
|---|---|
| `core` | Нажатие и отпускание уходят в ядро (`CMD_BTN`), ядро решает само (reset, NMI...). |
| `none` | Игнорируется. |
| `osd` | Открывает / закрывает меню OSD. |
| `menu` | Возврат в загрузочное меню. |
| `reload` | Загружает ядро заново (жёсткий сброс). |
| `bootsel` | Перезагружает MCU в BOOTSEL (обновление прошивки). |
| `msc` | Перезагружает в USB mass storage (SD-карта на ПК). |
| `msc2` | То же со второй SD-картой (слот FPGA). |

Если `press` — `core`, ядро получает нажатие сразу, а `hold` срабатывает, пока кнопка ещё нажата. При другом `press` короткое нажатие выполняет `press` при отпускании, а удержание — только `hold`.

```json
"buttons": {
    "btn1": "core",
    "btn2": {"press": "core", "hold": "menu", "hold_ms": 3000}
}
```

### LED-матрица

`matrix` задаёт, что показывает LED-матрица (16x8, красный / зелёный / жёлтый) в этом ядре. Значение — имя режима или объект:

| Ключ | Значение |
|---|---|
| `mode` | `core` (по умолчанию): матрицей управляет ядро (рисование или индикаторы звука); бут-ядро прокручивает `KARABAS GO`. `scroll`: бегущая строка `text`. `effect`: анимированный эффект `effect`. `image`: картинка или анимация до 4 кадров. `blank`: выключена. |
| `text` | `scroll`: до 64 ASCII-символов. `{name}`, `{build}`, `{time}` (ЧЧ:ММ) и `{date}` (ДД.ММ.ГГГГ) подставляются в начале каждого прохода. |
| `color` | `scroll`: `yellow` (по умолчанию), `red`, `green`, `rainbow` (по символам), `gradient` (по колонкам: зелёный, жёлтый, красный). Эффект `scanner`: `red` (по умолчанию), `green`, `yellow`. |
| `step_ms` | 20–5100 мс: сдвиг строки на пиксель, шаг эффекта, кадр анимации. По умолчанию: scroll 100, image 200, у эффекта свой. |
| `repeat` | `scroll`: число проходов текста, `image`: число циклов анимации (с одним кадром — шагов по `step_ms`). Затем включается `then`. `0` (по умолчанию): бесконечно. |
| `then` | После `repeat`: `core` (по умолчанию), `effect` или `blank`. |
| `effect` | `clock` (ЧЧ:ММ, секунды бегут по нижней строке), `fire` (огонь), `life` (игра «Жизнь»), `scanner` (бегающая точка), `rain` (дождь), `plasma` (плазма), `stars` (звёзды), `pong` (пинг-понг), `drive` (подключённые образы дисков: точка загорается при обращении, зелёная — чтение, красная — запись, жёлтым — положение головки по образу). |
| `brightness` | 1–16, по умолчанию 5. |
| `image` | Один кадр: 8 строк по 16 символов, `G` зелёный, `R` красный, `Y` жёлтый, `.` выключен. |
| `frames` | До 4 таких кадров — анимация. |

Ядро рисует на матрице (`CMD_MATRIX_*`) только в режиме `core` или после `then: core`.

```json
"matrix": {"mode": "scroll", "text": "NES {build}", "color": "rainbow", "repeat": 2,
           "then": "effect", "effect": "fire"}
```

### ROM

```json
"roms": [
    {"filename": "roms/ts-bios.rom", "address": 0},
    {"filename": "roms/gs105b.rom",  "address": 2147483648}
]
```

- `address` — 32-битный адрес назначения. Его смысл определяет ядро: например, TS-Conf по биту 31 (`0x80000000` = 2147483648) кладёт ROM в General Sound.
- ROM отправляются ядру в этом порядке при каждой загрузке ядра. См. `CMD_ROMLOADER` / `CMD_ROMDATA` в [описании протокола](https://github.com/andykarpov/karabas-go-firmware/blob/master/docs/protocol.ru.md).
- `"external": true` хранит в файле ядра только имя файла. Прошивка при каждом запуске ядра загружает ROM по этому пути с SD-карты, а если файла нет, показывает `NO FILE`. При сборке файла ядра сам ROM не нужен:

  ```json
  {"filename": "roms/zxnext.rom", "address": 0, "external": true}
  ```

### Пункты OSD

У каждого пункта есть `type` и `name` (не длиннее 16 символов, у текстовой строки — 32). **Номер** пункта в массиве — это номер переключателя, который ядро получает в `CMD_SWITCHES`. Не меняйте порядок пунктов без правки ядра.

| `type` | Пункт | Ключи | Что получает ядро |
|---|---|---|---|
| `S` | Переключатель: значение из списка, сохраняется в файле ядра. | `options` (≤ 16 строк, ≤ 16 символов; прошивка до древовидных меню показывает 8), `default`, `hotkey` | `CMD_SWITCHES (номер, значение)` при загрузке и при изменении. |
| `N` | Несохраняемый переключатель: как `S`, но значение не сохраняется. | как у `S` | то же. |
| `T` | Триггер: кнопка. | `hotkey` (`options: null`, `default: 0`) | `CMD_SWITCHES (номер, 1)`, через 100 мс `(номер, 0)`. |
| `H` | Скрытый триггер: как `T`, но не показывается в меню. | `hotkey` | как у `T`. |
| `P` | Текстовая строка, до 32 символов. | `name` | ничего. |
| `FL` | File loader: выбранный файл сразу отправляется ядру. | `slot` (0–7), `extensions`, `hotkey`, опционально `dir` / `filename` (файл по умолчанию), опционально `autoload` (bool: файл отправляется и при запуске ядра, если он есть) | последовательность `CMD_IOCTL_*`. |
| `M` | Вход на страницу: открывает пункты страницы `open` (подменю). | `open` (1–255, один `M` на страницу) | ничего. |
| `-` | Разделитель: линия. | — | ничего. |
| `F` | File mounter: подключение образа диска. | `slot` (0–7), `extensions`, `hotkey`, опционально `dir` / `filename`, опционально `physical` (bool: на плате с разъёмом дисковода, Karabas Go, браузер предлагает и физические дисководы) | `CMD_IMG_*`: ядро читает и пишет 512-байтные секторы образа; `CMD_IMG_PHYS` для физического дисковода. |

`default` — номер варианта по умолчанию. `hotkey` описан ниже. Пунктов до 64 (прошивка до древовидных меню читает 32).

### Подменю (страницы) и условные пункты

У любого пункта могут быть:

- `"page": n` (0–255, по умолчанию 0 = главное меню): пункт стоит на странице `n`. Страницу открывает пункт `M` с `"open": n`, который сам стоит на какой-то странице, поэтому страницы могут быть вложенными. `make_core.py` останавливается, если страницу не открывает ни один `M`, если её открывают дважды или если страницы образуют цикл.
- `"show_if"` или `"enable_if"`: `{"item": <номер или уникальное имя>, "value": <номер варианта (0–63) или его название>, "not": true|false}`. Пункт показывается (`show_if`) или доступен (`enable_if`, иначе рисуется серым), когда у переключателя `item` (`S` / `N` с вариантами) значение `value`, или наоборот при `"not": true`.

Номер пункта — по-прежнему его позиция в плоском массиве, на какой бы странице он ни стоял. Чтобы перевести плоское меню на дерево без правки ядра, сохраните порядок пунктов, добавьте `page` и допишите пункты `M` в конец. Горячие клавиши работают с любой страницы. Прошивка до древовидных меню показывает все пункты одним списком, а `M` и `-` — обычными строками.

```json
{"type": "S", "name": "Scanlines", "options": ["Off", "25%", "50%"], "default": 0, "page": 1},
{"type": "S", "name": "Scan color", "options": ["White", "Amber"], "default": 0, "page": 1,
 "enable_if": {"item": "Scanlines", "value": "Off", "not": true}},
{"type": "-"},
{"type": "M", "name": "Video", "open": 1}
``` Ключ `bits`, который встречается в JSON некоторых ядер, `make_core.py` игнорирует. Это лишь пометка, сколько бит ядро декодирует.

### Горячие клавиши

Горячая клавиша — это **ноль или несколько модификаторов и ровно одна клавиша** через `+`:

```
"Menu+F6"   "Ctrl+Alt+Del"   "F12"   "Menu+J"
```

- **Модификаторы:** `Ctrl`, `Shift`, `Alt`, `Menu` (клавиша Win / GUI). Левые и правые клавиши не различаются.
- **Клавиши:**
  - буквы `A`–`Z` и цифры `0`–`9`;
  - `F1`–`F12`;
  - `Enter`, `Esc`, `Bkspace`, `Tab`, `Space`, `Caps`;
  - `PtrScr`, `ScrLk`, `Pause`;
  - `Ins`, `Del`, `Home`, `End`, `PgUp`, `PgDn`;
  - `Up`, `Down`, `Left`, `Right`.
- Текст (≤ 16 символов) показывается в меню рядом с пунктом.
- **Заняты прошивкой:** `Menu+Esc` открывает и закрывает OSD, `Ctrl+Alt+Bkspace` перезагружает плату. Их не используйте.

`make_core.py` останавливается с ошибкой, если в горячей клавише нет клавиши, их две или встречается неизвестное название: такая горячая клавиша не поместится в 2 байта, которые читает прошивка. Пустая строка `""` означает, что горячей клавиши нет.

## Формат файла ядра (сигнатура `kgo1`)

Все многобайтные числа — **big-endian**. Строки — ASCII, дополненные пробелами (`make_core.py` пишет нули, если необязательного ключа нет). Прошивка читает поля по смещениям `FILE_POS_*` из своего `src/config.h`.

### Заголовок (1024 байта)

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 4 | Сигнатура `kgo1` |
| 4 | 32 | `id` |
| 36 | 32 | `name` |
| 68 | 8 | `build` |
| 76 | 1 | `visible` (1 / 0) |
| 77 | 1 | `order` |
| 78 | 1 | Тип: `0` boot, `1` osd, `2` fileloader, `255` без OSD |
| 79 | 1 | `eeprom_bank` |
| 80 | 4 | Длина битстрима `B` |
| 84 | 4 | Длина секции ROM `R` (данные всех ROM + 8 байт на каждый ROM) |
| 88 | 1 | `rtc_mode` |
| 89 | 32 | `dir` для file loader. Прошивка может его перезаписать. |
| 121 | 32 | `filename` для file loader. Прошивка хранит здесь последний выбранный файл: 16-битный номер в каталоге, байты 121–122. |
| 153 | 32 | `extensions` для file loader |
| 185 | 1 | `spi_freq` (МГц, `0` = 16 МГц) |
| 186 | 32 | `save_dir`, `FF`, если не задан |
| 218 | 18 | Кнопки `btn1`..`btn6`, по 3 байта: `press`, `hold` (действия: `0` core, `1` none, `2` osd, `3` menu, `4` reload, `5` bootsel, `6` msc, `7` msc2), `hold_ms` / 100. `FF` — не задано (`press`: core, без `hold`) |
| 236 | 20 | Резерв (`FF`) |
| 256 | 256 | Данные EEPROM для `eeprom_bank` 4–254. Пишет прошивка. |
| 512 | 256 | Значения переключателей OSD, по байту на пункт: сначала значения по умолчанию, затем сохранённые прошивкой. |
| 768 | 256 | LED-матрица: +0 режим (`0` core, `1` scroll, `2` effect, `3` image, `4` blank), +1 цвет, +2 `step_ms` / 20 (`0` по умолчанию), +3 `repeat`, +4 `then`, +5 эффект, +6 яркость (`0` по умолчанию), +7 число кадров, +16 текст (64), +80 четыре кадра по 32 байта (красная плоскость, зелёная, по 2 байта на строку, бит 7 — слева). `00` — core |

### Битстрим

Смещение 1024, `B` байт: `.bin` из ISE, уходит в FPGA как есть.

### Секция ROM

С `1024 + B`, всего `R` байт, по блоку на ROM:

| Размер | Поле |
|---|---|
| 4 | Длина данных. Бит 31 = внешний ROM: в данных имя файла на SD-карте. |
| 4 | Адрес назначения `address` |
| n | Данные ROM (или имя файла) |

### Секция OSD

С `1024 + B + R`:

| Размер | Поле |
|---|---|
| 1 | Число пунктов |
| … | Пункты подряд |

Один пункт:

| Размер | Поле |
|---|---|
| 1 | Тип: `0` S, `1` N, `2` T, `3` H, `4` P, `5` F, `6` FL, `7` M, `8` разделитель |
| 1 | Флаги: бит 0 = `physical` (только `F`), остальные биты — резерв (0) |
| 16 | Имя (у `P`: первые 16 символов текста) |
| 1 | Значение по умолчанию (у `M`: страница, которую он открывает) |
| | **Для `F` / `FL`:** |
| 1 | Слот (биты 0–6), флаг автозагрузки (бит 7) |
| 256 | Расширения |
| 256 | Каталог, дополненный нулями. Прошивка записывает сюда последний каталог. |
| 256 | Имя файла, дополненное нулями. Прошивка записывает сюда последний файл. |
| | **Для остальных типов:** |
| 1 | Число вариантов `n` (прошивка читает не больше 16, до древовидных меню — 8) |
| 16 × n | Названия вариантов |
| | **Для всех типов:** |
| 16 | Текст горячей клавиши (у `P`: символы 17–32 текста) |
| 2 | Коды горячей клавиши: маска модификаторов (Ctrl `11`, Shift `22`, Alt `44`, Menu `88`, через ИЛИ), USB HID код клавиши |
| 1 | Страница пункта (0 = главное меню) |
| 1 | Условие: номер + 1 переключателя, от которого зависит пункт, 0 = нет |
| 1 | Условие: бит 7 — сделать недоступным (иначе скрыть), бит 6 — инверсия, биты 0–5 — значение. Пункт показан / доступен, когда (значение переключателя == значение) xor инверсия |

Значение по умолчанию каждого пункта также записывается в его байт по смещению 512 + номер.
